# Sample scenarios

Generated by `scripts/make_more_samples.py`. Upload the two files of a folder with `POST /api/files`, then reconcile.

Scenarios marked *needs an LLM key* use a bank or register layout the service has not seen; set `GEMINI_API_KEY` (or `LLM_PROVIDER=claude` + `ANTHROPIC_API_KEY`) first, otherwise the API answers 503.

- **01_all_matched**: Known layout. Every payout paid once with its Payout ID: everything matches, nothing needs review.
- **02_hdfc_style_new_layout**: NEW bank layout (needs an LLM key): 'Withdrawal Amt.'/'Deposit Amt.', dd/mm/yy dates, numeric cells, statement-summary footer. Mixed outcomes: ID matches, name/account matches, amount mismatch, returned payout, missing payouts, unrelated debits.
- **03_icici_style_newest_first**: NEW bank layout (needs an LLM key): newest-first, timestamps in the transaction date, one amount column plus a Cr/Dr column, two date columns. Mixed outcomes.
- **04_signed_amount_csv**: NEW bank layout (needs an LLM key), CSV: single signed Amount column (negative = debit), dd-Mon-yyyy dates. Mixed outcomes.
- **05_broken_statement**: Known layout, damaged export: a missing row (balance break), a duplicated row, an impossible date, an amount typed with a letter O, and a second sheet that is not read. Expect P1 integrity items, unreadable rows listed, and totals that still tie.
- **06_no_balance_column**: NEW bank layout (needs an LLM key) with NO balance column: the layout cannot be proven, so it is saved as 'pending review' and flagged until approved with scripts/approve_layout.py.
- **07_renamed_register**: Payout register exported with renamed and reordered columns (needs an LLM key). The bank layout is known. A new register layout is always held for review.
- **08_large_volume**: Known layout, volume test: 3,000 payouts over a month with a realistic mix of outcomes.
